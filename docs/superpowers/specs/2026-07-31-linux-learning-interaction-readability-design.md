# Linux 学习站交互与可读性修复设计

日期：2026-07-31

## 背景

网站面向嵌入式 Linux 初学者，核心体验由“安装系统”和“使用 Linux”两部分组成。当前命令行实验室左侧虽然展示课程列表，但列表项是静态文本，无法选择课程；右侧学习提示和推荐命令也不会随课程变化。与此同时，多处提示、说明、标签和命令描述采用 7–10px 字号，影响阅读。部分懒加载页面在资源加载期间没有明确反馈，容易被误认为页面失效。

本次工作以模拟 Linux 教学体验为边界，不引入真实云端 Linux 容器，也不改变现有的免费静态部署模式。

## 目标

1. 让命令行页的课程真正可选，并在当前页面内驱动学习提示和练习内容。
2. 建立全站统一的辅助文字可读性下限，重点改善命令行旁的学习区域。
3. 修复通过系统性 QA 发现的同类交互缺陷，包括无效控件、流程无法推进和缺少加载反馈。
4. 保持安装模拟、命令模拟、课程内容与本地学习进度之间的一致性。
5. 使用自动化测试和浏览器验收覆盖关键路径，并确保键盘和移动端可用。

## 非目标

- 不在浏览器中启动真实 Ubuntu、Debian 或 Buildroot 虚拟机。
- 不承诺模拟任意 Linux 软件包和所有现实世界命令组合。
- 不增加必须付费的后端、数据库或 Vercel 服务。
- 不在本次改动中重写整个视觉主题或课程体系。

## 已确认的交互方案

采用“命令行页内伴学”方案：选择左侧课程后不离开命令行页，右侧内容同步切换，并提供进入完整课程页的入口。

与“点击后直接跳转课程页”相比，该方案能保留终端上下文，更适合边看提示边练习；与把所有课程内容完整堆进实验室相比，它保持页面聚焦，并复用现有完整课程页。

## 信息架构与状态

### 课程数据

课程名称、目标、说明、练习命令、完成条件和完整课程标识应来自共享课程数据，而不是在 `LabPage` 中维护另一套孤立文案。实验室可以展示适合快速练习的课程子集，但每项必须能映射到完整课程。

### 实验室状态

`LabPage` 维护当前选中的课程标识。默认选中第一个适合当前阶段的课程；如果 URL 中包含有效课程参数，则优先打开该课程。无效参数安全回退到默认课程。

选择课程后：

- 左侧按钮显示明确的选中状态和当前课程语义。
- 右侧更新学习目标、用途说明、推荐命令、快捷提示和完成条件。
- “打开完整课程”链接携带课程标识，使课程页直接定位到同一课。
- 终端历史、当前目录和模拟系统状态不会因为切换课程而重置。

### 完整课程页

`CoursesPage` 读取课程参数并定位到对应课程。用户在课程页切换课程时，页面状态和 URL 保持一致；刷新后仍可恢复。既有本地学习进度继续使用浏览器存储，不要求登录。

## 组件交互设计

### 左侧课程列表

- 使用原生 `button`，不使用伪装成可点击区域的静态 `li`。
- 支持鼠标、触摸、Tab、Enter 和 Space。
- 当前课程使用 `aria-current` 或等价的可访问状态。
- 每项显示课程标题和一行简短目标；焦点、悬停、选中三种状态视觉上可区分。

### 右侧学习提示

每节课统一展示：

1. 本节目标。
2. 命令在真实 Linux 或嵌入式开发中的用途。
3. 1–4 条推荐练习命令。
4. 必要的风险说明或模拟边界。
5. 可观察的完成条件。

推荐命令提供“填入终端”操作。该操作只将命令放入输入框，不自动执行，避免用户在未阅读命令时触发操作。复制命令作为辅助操作保留。

### 页面加载反馈

懒加载路由必须显示与网站风格一致的加载状态，不能留下空白页面。加载失败时显示可恢复的错误提示和重试入口。

## 可读性规范

本次不简单地整体放大页面，而是按文字职责设置下限：

- 页面正文、课程说明和学习提示：至少 13px。
- 命令说明、结果说明、表单帮助与安装解释：至少 12px。
- 标签、状态、元数据、快捷键说明：至少 11px。
- 主要交互控件的可点击区域：桌面端和触摸端均不得依赖文字本身的高度。
- 终端等宽文字保持清晰，移动端允许适度缩小，但不低于可读性下限。

重点检查 `HomePage`、`InstallPage`、`LabPage`、`CommandsPage`、`CoursesPage` 和 `AboutPage`，避免仅修复用户指出的一处。

## 系统性缺陷审计范围

### 安装模拟

- Ubuntu、Debian、Buildroot 选择是否正确改变流程内容。
- 磁盘分区、网络、用户、软件选择和完成步骤能否前进、返回和恢复。
- 禁止条件、错误状态和完成后的入口是否明确。

### 命令行模拟

- Tab 补全、上下历史、清屏、中断和常见重定向。
- 课程推荐命令填入后能否编辑和执行。
- 命令输出、错误信息和当前目录状态是否一致。
- 不支持的命令给出教学性反馈，而不是假装成功。

### 命令库

- 搜索、分类、展开、复制、示例和风险标签。
- 命令库内容与模拟器实际支持能力的边界说明。
- 基础命令、软件包管理、进程、网络、权限、存储和嵌入式工具链分类的可发现性。

### 课程页

- 课程选择、下一课、上一课、进度记录和 URL 定位。
- 已完成、当前、未开始状态的正确展示。
- 页面刷新后状态恢复。

### 全站

- 导航链接、按钮和折叠项不存在静态假控件。
- 键盘焦点可见，语义和可访问名称完整。
- 懒加载期间有反馈。
- 常见桌面和移动宽度下不出现遮挡或关键内容溢出。

## 测试策略

实现采用测试驱动方式：先增加能稳定复现缺陷的失败测试，再编写最小修复。

### 组件与单元测试

- 实验室课程项可被按钮语义查询，点击后右侧内容更新。
- 推荐命令“填入终端”不会自动执行，并保留现有终端状态。
- 实验室和完整课程页能处理有效、无效课程参数。
- 页面加载和失败状态有可感知内容。
- 安装模型、命令模拟器和课程进度的现有测试不得回归。

### 浏览器验收

- 按真实用户路径逐页检查首页、安装、实验室、命令库、课程和关于页。
- 使用鼠标和键盘完成课程选择及命令练习。
- 完成一遍 Ubuntu 和 Debian 安装模拟的关键步骤。
- 验证命令搜索、复制、Tab 补全、历史记录和错误反馈。
- 在桌面与移动视口检查字号、焦点、溢出和加载状态。
- 检查控制台错误和未处理异常。

## 完成标准

- 命令行页课程可点击、可键盘操作，右侧内容按选中课程正确更新。
- 推荐命令可安全填入终端，完整课程入口定位正确。
- 六个主要页面不再存在低于本设计下限的正常可见辅助文本，装饰性图形文字除外。
- 安装、课程、命令库和终端的关键路径均通过自动化测试与浏览器验收。
- 构建成功，生产部署不需要新增付费服务或后端依赖。
- QA 中发现的额外问题必须记录：在本次范围内的直接修复，超出范围的形成明确后续项。

## 风险与边界

- 课程数据结构调整可能影响现有测试和本地进度键名，应采用兼容迁移或稳定标识。
- 外部控制终端输入需要清晰的数据流，避免通过 DOM 操作绕过 React 状态。
- 统一提高字号可能引起窄屏换行和卡片高度变化，必须配合响应式浏览器验收。
- “真实体验”指行为、提示和结果尽量符合 Linux 学习场景；模拟器仍需明确标注能力边界，不能暗示它是完整 Linux 内核环境。
